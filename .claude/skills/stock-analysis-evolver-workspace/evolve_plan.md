# Evolve Plan: stock-analysis

## 目标
提升 stock-analysis skill 在真实执行场景中的明确性和鲁棒性，重点攻克以下方向：
1. 触发词覆盖（L1 frontmatter）
2. 执行流程中的歧义消除（L2 正文）
3. 边界场景处理的明确性（L2 正文）

## Baseline 评估

**静态评测 pass_rate：1.00（25/25 expectations 全通过）**

这说明 SKILL.md 的整体结构完善，规则覆盖全面。然而通过深度阅读发现以下潜在问题（即使 GT case 全过，在真实执行中仍可能出错）：

### 已识别的薄弱点（按严重性排序）

1. **[严重] 批量模式找不到股票时的处理歧义**
   - 当前描述："如有找不到的股票，告知用户，询问是跳过还是停止"
   - 问题：没有说明如果用户选择"跳过"，跳过后继续的执行逻辑是否与原来一致
   - 风险：agent 可能在跳过后忘记更新进度计数或总览统计

2. **[中等] 触发词覆盖不够全面**
   - 当前 description 中的触发词偏正式（"做个全面分析"、"投资分析"）
   - 遗漏常见口语：比如"XX 怎么样"、"看看 XX"、"XX 值得买吗"
   - 风险：用户用口语触发时 skill 未被激活

3. **[中等] 数据单位换算规则分散**
   - 注意事项中的换算规则（trade_stock_financial 是元、financial_income 是亿元、total_mv 是万元）分散在数据源说明中
   - 风险：agent 在生成报告时可能混用单位，导致财务数据错误

4. **[轻微] 可比公司选择标准不明确**
   - 当前只说"根据公司所在行业"，没有说明如何选择 2-5 家公司
   - 风险：agent 可能选择不相关的公司，或主观选择质量参差不齐

5. **[轻微] 题材批量模式进度报告格式**
   - 当前进度报告是内联格式，缺少对已完成只数的完整统计
   - 风险：用户在批量分析多只股票时对进度不清晰

## 评测策略

- Dev 集：7 个 GT cases（id 1-7）
- Holdout 集：3 个 GT cases（id 101-103）
- 门控阈值：pass_rate ≥ baseline（1.00），不得退步；期望每轮在真实执行质量上有提升
