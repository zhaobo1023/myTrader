# A 股分析（单股 / 题材批量）

基于 myTrader 系统（ECS MySQL）的全量 A 股数据，结合 Claude Financial Services 插件分析框架，支持两种模式：
- **单股模式**：对单只股票生成八章节完整报告
- **题材批量模式**：对用户指定的一批股票逐只分析，并生成题材总览报告

## 分工（不要越界）

| 谁 | 做什么 |
|---|---|
| `scripts/fetch_stock_data.py` | 连库、拉九项数据、代码格式重试、单位换算、统计数据完备性 |
| 你（模型） | 判断数据够不够做结论、缺失时要不要继续、公司定位、竞争格局、估值假设、投资观点、分档定级 |

脚本只做**事实陈述**（"财务数据 2 个报告期"），不做处置决策。
"数据不足要不要问用户"、"这个估值算贵还是便宜"取决于用户意图和行业语境，
硬编码规则只会给出看起来合理但实际没用的判断。

## 参考文件（按需读，不要一次全读）

| 文件 | 什么时候读 |
|---|---|
| `references/report-template.md` | 生成报告正文时（八章节 / 六章节 / 题材总览的详细结构） |
| `references/dcf-params.md` | 写 DCF 估值章节时 |
| `references/technical-signals.md` | 写技术面与动量章节时 |
| `references/db-schema.md` | 只在需要手写脚本未覆盖的 SQL 时 |

## 输入解析

### 模式判断

- 用户给出**单只股票**名称或代码 → 进入**单股模式**
- 用户给出**题材名 + 多只股票列表**，或说"批量分析"、"题材分析" → 进入**题材批量模式**
- 模式不明确时，询问用户："请问是分析单只股票，还是针对某个题材批量分析一组股票？"

### 单股模式输入
1. **公司名称或股票代码**（必须） — 如"长电科技"、"600584"、"贵州茅台"
2. **输出路径**（可选） — 默认 `~/Documents/notes/Finance/`

### 题材批量模式输入
1. **题材名称**（必须） — 如"AI算力"、"半导体设备"、"低空经济"
2. **个股列表**（必须） — 由用户给出，可以是名称或代码，如"中际旭创、天孚通信、光迅科技"
3. **输出路径**（可选） — 默认 `~/Documents/notes/Finance/{题材名}/`

如果题材批量模式下用户未给出个股列表，主动询问："请列出要分析的个股（名称或代码均可）。"

## 工作流程 — 单股模式

### Step 1: 确认公司信息

```bash
python .claude/skills/stock-analysis/scripts/fetch_stock_data.py --resolve "长电科技"
```

返回匹配的股票代码与名称。**找不到时告知用户并停止**，不要猜代码、不要继续分析。

### Step 2: 拉取全部数据

```bash
python .claude/skills/stock-analysis/scripts/fetch_stock_data.py --code 600584.SH --json
```

一次拉齐九项：财务汇总、利润表、资产负债表、现金流量表、最新估值、近期行情、
技术因子、公司公告、最新新闻。金额已统一换算为亿元。

脚本 exit code 非 0 时读 stderr 告知用户原因，不要用不完整数据硬写报告。

### Step 3: 数据完备性检查

脚本输出的 `completeness` 字段已给出各项实际期数。按下表判断：

| 检查项 | 最低要求 | 缺失处理 |
|---|---|---|
| 财务数据 | 至少 4 个年度报告 | 告知"财务数据不足，无法做趋势分析" |
| 现金流数据 | 至少 3 个年度 | 告知"现金流数据不足，盈利质量分析受限" |
| 资产负债数据 | 至少 2 个报告期 | 告知"资产负债数据不足，无法评估杠杆" |
| 估值数据 | 当前 PE/PB | 告知"估值数据缺失" |
| 行情数据 | 至少 10 个交易日 | 告知"行情数据不足" |

**如果关键数据缺失严重（财务数据 < 2 年），先询问用户是否继续，不要直接生成不完整的报告。**

### Step 4: 查找可比公司

```bash
python .claude/skills/stock-analysis/scripts/fetch_stock_data.py --code 600584.SH --peers
```

脚本按 `trade_stock_info.industry` 取同行业、按市值从大到小返回 2-5 家，
并拉齐它们的最新估值与年报数据（统一时间基准，避免横向对比失真）。

优先选规模相近、业务相似的公司——脚本按市值排序给候选，**是否合适由你判断**，
明显不可比的（如主业完全不同的多元化集团）剔除并说明。

若某家可比公司某项数据缺失，在对比表格对应单元格标注 `N/A`，
不跳过该公司（保留行），不影响整行其他数据的展示。

### Step 5: 生成分析报告（八章节）

结构见 `references/report-template.md`。写 DCF 章节前读 `references/dcf-params.md`，
写技术面章节前读 `references/technical-signals.md`。

### Step 6: 写入文档

将完整报告写入 `~/Documents/notes/Finance/` 目录：
- 文件名格式：`{公司名}-全面分析-{YYYYMMDD}.md`
- 使用 Markdown 格式，表格对齐，数字保留合理精度
- **文件已存在时**：直接覆盖（同日重跑视为更新），不询问用户。写入后在 Step 7 汇报时注明"（已覆盖旧文件）"

### Step 7: 向用户汇报

1. 报告已写入的文件路径
2. 关键发现摘要（2-3 句）
3. 如有数据缺失，列出缺失项

## 工作流程 — 题材批量模式

### Phase 0: 确认个股列表

批量执行前，向用户确认：
- 题材名称：`{题材名}`
- 个股列表：逐一列出，附股票代码（若用户给的是名称则先用 `--resolve` 确认）
- 输出目录：`~/Documents/notes/Finance/{题材名}/`
- 预计生成文件数：N 只个股报告 + 1 份题材总览

如有找不到的股票，告知用户，询问是跳过还是停止。
- 用户选择**停止**：终止整个批量分析任务。
- 用户选择**跳过**：从个股列表中移除该股票，更新总数 N，继续后续流程。后续进度报告以更新后的 N 为基准（如原来 4 只，跳过 1 只后变为 [1/3]、[2/3]、[3/3]）。题材总览横向对比表中不出现已跳过的股票。

### Phase 1: 批量拉取公共数据

```bash
python .claude/skills/stock-analysis/scripts/fetch_stock_data.py --codes 600584.SH,688981.SH,... --overview
```

一次性拉齐所有个股的最新估值、财务摘要、基础因子（用 IN 批量查询，减少连接次数），
用于后续题材总览横向对比。

### Phase 2: 逐股深度分析（顺序执行）

对列表中每只股票，按顺序执行（**不并发**，避免 SSH 连接过多）。

**每只股票开始前**，向用户报告进度：`[{i}/{N}] 正在分析：{公司名}（{代码}）`

数据拉取用 Step 2 的同一条命令。完备性检查标准与单股模式相同，
但**批量模式下的处理逻辑不同**：

- **轻微缺失**（现金流 < 3 年、资产负债 < 2 期、估值/行情不足）：在个股报告对应章节标注缺失原因，继续分析，**不中断批量流程**。
- **严重缺失**（财务数据 < 2 年）：在个股报告第一行以 `> [数据警告]` 格式标注财务数据严重不足，继续生成报告（但财报分析章节明确说明无法做趋势分析），**不询问用户、不中断流程**。在 Phase 4 汇报时集中列出所有严重缺失的股票及缺失项。

批量模式下**不暂停流程询问用户**（因为用户已明确启动批量任务），所有缺失情况统一在 Phase 4 结尾汇总报告。

**生成精简版报告（六章节）**：结构见 `references/report-template.md`。

**写入个股文件**：
- 路径：`~/Documents/notes/Finance/{题材名}/{公司名}-分析-{YYYYMMDD}.md`
- 文件已存在时直接覆盖，不中断流程
- 完成后向用户报告：`[{i}/{N}] 完成：{公司名} → {文件路径}`

### Phase 3: 生成题材总览报告

写入 `~/Documents/notes/Finance/{题材名}/{题材名}-题材总览-{YYYYMMDD}.md`，
五部分结构（题材背景 / 横向对比表 / 分档评级 / 行业与竞争格局 / 精选标的）
见 `references/report-template.md`。

### Phase 4: 向用户汇报

```
题材分析完成：{题材名}
个股报告：{N} 份，路径：~/Documents/notes/Finance/{题材名}/
总览报告：{题材名}-题材总览-{YYYYMMDD}.md

精选标的：{公司A}、{公司B}
数据缺失：{若有，列出哪只股票缺了什么}
```

## 约束

- 所有分析基于 myTrader 系统中的实际数据，**不编造数字**
- 估值参数明确标注来源和假设
- 区分事实和分析，分析部分标注"判断"/"估计"
- 报告末尾必须包含免责声明
- 不使用 emoji

## 已知陷阱

- **`trade_stock_financial` 里没有营收和净利润**，只有比率（ROE、毛利率、EPS 等）。
  营收/净利在 `financial_income`。从前者取营收会拿不到数，容易误判为"这家公司没财务数据"。
- **不同表的金额单位不一致**：`financial_*` 已是亿元，`total_mv`/`circ_mv` 是万元。
  混用会让报告里的数字差 4 个数量级。脚本已统一换算为亿元；
  手写 SQL 时必须查 `references/db-schema.md` 的换算表。
- **代码列叫 `stock_code` 不是 `ts_code`**：写成 `ts_code` 会报 Unknown column。
- **股票代码格式在财务表里不统一**：`research_announcements` 等表可能存纯 6 位数字
  而非 `600584.SH`。直接用带后缀格式查会**静默返回 0 行**（不是报错），
  容易被当成"这家公司没有公告"。脚本已内置 0 行时换格式重试。
- **同比增速遇负基数会算出无意义的百分比**：上年亏损、本年盈利时，
  按公式算出的增速（如 -250%）方向是反的。必须按
  `references/report-template.md` 的四情形表处理，扭亏/转亏要单独标注。
- **可比公司估值必须同一交易日**：不同股票取各自"最新"交易日会导致
  横向对比失真（有的停牌、有的最新数据滞后）。脚本已统一基准日。
- **批量模式不要因为单只股票数据缺失就停下问用户**：用户已明确启动批量任务，
  中途打断会让整批白跑。缺失信息统一到 Phase 4 汇总。
