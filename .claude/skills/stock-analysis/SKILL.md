# A 股分析（单股 / 题材批量）

基于 myTrader 系统（ECS MySQL）的全量 A 股数据，结合 Claude Financial Services 插件分析框架，支持两种模式：
- **单股模式**：对单只股票生成八章节完整报告
- **题材批量模式**：对用户指定的一批股票逐只分析，并生成题材总览报告

## 输入解析

### 模式判断

- 用户给出**单只股票**名称或代码 → 进入**单股模式**
- 用户给出**题材名 + 多只股票列表**，或说"批量分析"、"题材分析" → 进入**题材批量模式**
- 模式不明确时，询问用户："请问是分析单只股票，还是针对某个题材批量分析一组股票？"

### 单股模式输入
1. **公司名称或股票代码**（必须） — 如"长电科技"、"600584"、"贵州茅台"
2. **输出路径**（可选） — 默认 `~/Documents/notes/Finance/`

### 题材批量模式输入
1. **题材名称**（必须） — 如"AI算力"、"半导体设备"、"低空经济"
2. **个股列表**（必须） — 由用户给出，可以是名称或代码，如"中际旭创、天孚通信、光迅科技"
3. **输出路径**（可选） — 默认 `~/Documents/notes/Finance/{题材名}/`

如果题材批量模式下用户未给出个股列表，主动询问："请列出要分析的个股（名称或代码均可）。"

## 数据源

所有数据从 ECS MySQL 获取。连接方式：

```bash
ssh aliyun-ecs "mysql -u mytrader_user -p'lGgS^uruPhv%AK0ZifeC' trade -e \"SQL\""
```

### 核心数据表

| 表 | 内容 | 日期列 |
|---|---|---|
| `trade_stock_info` | 股票名称→代码映射 | - |
| `trade_stock_daily` | 日线行情 OHLCV | `trade_date` |
| `trade_stock_daily_basic` | 估值：总市值、PE/PB/PS | `trade_date` |
| `trade_stock_financial` | 财务汇总：营收、净利、ROE、毛利率等 | `report_date` |
| `financial_income` | 利润表明细（亿元） | `report_date` |
| `financial_balance` | 资产负债表明细（亿元） | `report_date` |
| `financial_cashflow` | 现金流量表（亿元） | `report_date` |
| `financial_dividend` | 分红历史 | `ex_date` |
| `trade_stock_basic_factor` | 基础因子：动量、换手、波动率 | `calc_date` |
| `trade_stock_valuation_factor` | 估值因子：PE/PB/PS/市值 | `calc_date` |
| `trade_technical_indicator` | 技术指标：MA/MACD/RSI/KDJ | `trade_date` |
| `stock_news` | 新闻 | - |
| `research_announcements` | 公司公告 | `ann_date` |

### 注意事项

**单位换算速查表（生成报告时统一换算为亿元）：**

| 数据表 | 字段 | 原始单位 | 换算方式 | 报告中单位 |
|---|---|---|---|---|
| `trade_stock_financial` | 营收/净利等金额 | 元 | ÷ 1e8 | 亿元 |
| `financial_income` | 所有金额 | 亿元 | 无需换算 | 亿元 |
| `financial_balance` | 所有金额 | 亿元 | 无需换算 | 亿元 |
| `financial_cashflow` | 所有金额 | 亿元 | 无需换算 | 亿元 |
| `trade_stock_daily_basic` | `total_mv`（总市值） | 万元 | ÷ 10000 | 亿元 |

**股票代码格式**：标准格式为 `600584.SH`（带后缀）。`financial_income` 等财务表中可能不带后缀（`600584`），查询时两种都试。

## 工作流程 — 单股模式

### Step 1: 确认公司信息

查询 `trade_stock_info` 确认股票代码和名称。如果找不到，告知用户并停止。

### Step 2: 拉取全部数据（并行）

一次性并行拉取以下数据（每个查询一个 Bash 调用）：

1. **财务汇总** — `trade_stock_financial` 最近 12 个报告期
2. **利润表明细** — `financial_income` 最近 12 个报告期
3. **资产负债表** — `financial_balance` 最近 8 个报告期
4. **现金流量表** — `financial_cashflow` 最近 8 个报告期
5. **最新估值** — `trade_stock_daily_basic` 最近 5 个交易日
6. **近期行情** — `trade_stock_daily` 最近 20 个交易日
7. **技术因子** — `trade_stock_basic_factor` 最近 5 个交易日
8. **公司公告** — `research_announcements` 最近 10 条。代码格式策略：优先用带后缀格式（`600584.SH`）查询；若返回 0 行，再改用纯 6 位数字（`600584`）重试一次
9. **最新新闻** — `stock_news` 最近 5 条

### Step 3: 数据完备性检查

**逐项检查数据是否充分，如有缺失必须明确告知用户：**

| 检查项 | 最低要求 | 缺失处理 |
|---|---|---|
| 财务数据 | 至少 4 个年度报告 | 告知"财务数据不足，无法做趋势分析" |
| 现金流数据 | 至少 3 个年度 | 告知"现金流数据不足，盈利质量分析受限" |
| 资产负债数据 | 至少 2 个报告期 | 告知"资产负债数据不足，无法评估杠杆" |
| 估值数据 | 当前 PE/PB | 告知"估值数据缺失" |
| 行情数据 | 至少 10 个交易日 | 告知"行情数据不足" |

**如果关键数据缺失严重（财务数据 < 2 年），先询问用户是否继续，不要直接生成不完整的报告。**

### Step 4: 查找可比公司

根据公司所在行业，查找 2-5 家同行业可比公司：

1. **确定行业**：查询 `trade_stock_info` 的 `industry` 字段获取当前公司的行业分类
2. **筛选可比公司**：用 `WHERE industry = '<行业>' AND ts_code != '<当前代码>'` 查同行业股票，按市值从大到小选取 2-5 家（优先选规模相近、业务相似的公司）
3. **拉取数据**：并行拉取可比公司的 `trade_stock_daily_basic`（最新日估值）和 `trade_stock_financial`（最新年报）
4. **同一时间基准**：确保所有可比公司估值数据使用**同一交易日**，避免横向对比失真
5. **数据缺失处理**：若某家可比公司某项数据缺失，在对比表格对应单元格标注 `N/A`，不跳过该公司（保留行），不影响整行其他数据的展示

### Step 5: 生成分析报告（八章节）

#### 第一章：公司概览
- 一句话定位（行业、排名、主营业务）
- 主要客户/产品

#### 第二章：财报分析
- 营收/净利润 3 年趋势 + 同比增速
- 毛利率/净利率/ROE 趋势
- 最新季度 vs 去年同期对比
- 盈利质量：经营现金流/净利润比率（至少 3 年）

#### 第三章：可比公司分析
- 同行业 3-5 家公司对比表格（市值、PE、PB、PS、营收、净利、毛利率、ROE）
- 统计摘要（最大值、75%/50%/25%分位、最小值）
- 关键发现：估值高低、盈利效率对比

#### 第四章：DCF 估值框架
- **参数基准**：
  - 无风险利率：中国 10Y 国债收益率（约 1.7%，若有更新数据以实际为准）
  - Beta：使用 `trade_stock_basic_factor` 中的 beta 字段（相对沪深300）；若数据缺失，参考行业均值并注明
  - ERP（股权风险溢价）：Bear 情景取 7%，Base 取 6%，Bull 取 5%
  - WACC：由无风险利率 + Beta × ERP 估算（纯股权简化版），如有负债结构数据则加权
  - 终端增速：Bear 取 2%，Base 取 3%，Bull 取 4%（不超过名义 GDP 增速上限）
- 三情景估值（Bear/Base/Bull），列出每情景的关键假设和估算市值
- 敏感性分析表（WACC vs 终端增速），WACC 范围 ±1%，终端增速范围 ±1%
- 当前市值在估值区间中的位置（高估/合理/低估判断）

#### 第五章：竞争格局
- 行业全球/全国排名
- 核心竞争壁垒评估
- 主要风险

#### 第六章：行业研究
- 行业周期定位
- 增长驱动因素
- 核心风险

#### 第七章：技术面与动量
- 股价、20/60 日动量、波动率、换手率
- 简要技术面信号解读（依据以下判断规则）：

  | 指标 | 信号 | 判断标准 |
  |---|---|---|
  | RSI（14日） | 超买 | RSI > 70 |
  | RSI（14日） | 超卖 | RSI < 30 |
  | RSI（14日） | 中性 | 30 ≤ RSI ≤ 70 |
  | MACD | 金叉（偏多） | DIF 从下方穿越 DEA，且 MACD 柱由负转正 |
  | MACD | 死叉（偏空） | DIF 从上方穿越 DEA，且 MACD 柱由正转负 |
  | MACD | 顶/底背离 | 股价创新高/低但 DIF 未跟随 |
  | KDJ | 超买 | K > 80 且 D > 80 |
  | KDJ | 超卖 | K < 20 且 D < 20 |
  | KDJ | 金叉（偏多） | K 从下方穿越 D，且处于低位（D < 50） |
  | KDJ | 死叉（偏空） | K 从上方穿越 D，且处于高位（D > 50） |
  | MA | 多头排列 | MA5 > MA20 > MA60，股价在 MA5 上方 |
  | MA | 空头排列 | MA5 < MA20 < MA60，股价在 MA5 下方 |
  | MA | 黄金交叉 | MA20 上穿 MA60 |
  | MA | 死亡交叉 | MA20 下穿 MA60 |

  若技术指标数据缺失，在该章节注明"技术指标数据不可用"，跳过信号解读。

#### 第八章：投资观点卡片
- 核心观点（1-2 句话）
- 投资支柱（2-3 条）+ 风险（2-3 条），附信心度
- 催化剂列表
- 目标价区间 + 止损线
- **免责声明：本分析仅供参考，不构成投资建议**

### Step 6: 写入文档

将完整报告写入 `~/Documents/notes/Finance/` 目录：
- 文件名格式：`{公司名}-全面分析-{YYYYMMDD}.md`
- 使用 Markdown 格式
- 表格对齐，数字保留合理精度
- **文件已存在时**：直接覆盖（同日重跑视为更新），不询问用户。写入后在 Step 7 汇报时注明"（已覆盖旧文件）"

### Step 7: 向用户汇报

简要汇报：
1. 报告已写入的文件路径
2. 关键发现摘要（2-3 句）
3. 如有数据缺失，列出缺失项

## 工作流程 — 题材批量模式

### Phase 0: 确认个股列表

批量执行前，向用户确认：
- 题材名称：`{题材名}`
- 个股列表：逐一列出，附股票代码（若用户给的是名称则先查 `trade_stock_info` 确认）
- 输出目录：`~/Documents/notes/Finance/{题材名}/`
- 预计生成文件数：N 只个股报告 + 1 份题材总览

如有找不到的股票，告知用户，询问是跳过还是停止。
- 用户选择**停止**：终止整个批量分析任务。
- 用户选择**跳过**：从个股列表中移除该股票，更新总数 N，继续后续流程。后续进度报告以更新后的 N 为基准（如原来 4 只，跳过 1 只后变为 [1/3]、[2/3]、[3/3]）。题材总览横向对比表中不出现已跳过的股票。

### Phase 1: 批量拉取公共数据

在逐股分析之前，先一次性并行拉取所有股票的轻量数据，用于后续题材总览横向对比：

- 所有个股最新估值：`trade_stock_daily_basic`（最近 1 个交易日，IN 一批代码）
- 所有个股最新财务摘要：`trade_stock_financial`（最近年报，IN 一批代码）
- 所有个股最新因子：`trade_stock_basic_factor`（最近 1 个交易日，IN 一批代码）

SQL 示例（用 IN 批量查询，减少连接次数）：
```sql
SELECT ts_code, total_mv, pe_ttm, pb, ps_ttm
FROM trade_stock_daily_basic
WHERE ts_code IN ('600584.SH','688981.SH',...)
  AND trade_date = (SELECT MAX(trade_date) FROM trade_stock_daily_basic)
```

### Phase 2: 逐股深度分析（顺序执行）

对列表中每只股票，按顺序执行以下步骤（**不并发**，避免 SSH 连接过多）：

**每只股票开始前**，向用户报告进度：`[{i}/{N}] 正在分析：{公司名}（{代码}）`

#### 数据拉取（并行，与单股模式相同）
拉取该股票的完整数据（Step 2 的全部 9 项），并行执行。

#### 数据完备性检查
检查标准与单股模式相同（同一张缺失检查表），但批量模式下的处理逻辑不同：

- **轻微缺失**（现金流 < 3 年、资产负债 < 2 期、估值/行情不足）：在个股报告对应章节标注缺失原因，继续分析，**不中断批量流程**。
- **严重缺失**（财务数据 < 2 年）：在个股报告第一行以 `> [数据警告]` 格式标注财务数据严重不足，继续生成报告（但财报分析章节明确说明无法做趋势分析），**不询问用户、不中断流程**。在 Phase 4 汇报时集中列出所有严重缺失的股票及缺失项。

批量模式下**不暂停流程询问用户**（因为用户已明确启动批量任务），所有缺失情况统一在 Phase 4 结尾汇总报告。

#### 生成精简版报告（六章节）

题材批量模式下，个股报告**去掉单股模式的"第三章可比公司分析"和"第六章行业研究"**：
- "可比公司分析"合并进题材总览的"二、横向对比表"（题材内所有股票并排对比）
- "行业研究"合并进题材总览的"四、行业与竞争格局"（题材层面统一分析，不在每只个股报告重复）

保留以下六章（章节编号重新排列，无跳号）：

| 批量报告章节 | 对应单股模式章节 |
|---|---|
| 第一章：公司概览 | 第一章（不变） |
| 第二章：财报分析 | 第二章（不变） |
| 第三章：DCF 估值框架 | 原第四章 |
| 第四章：竞争格局 | 原第五章 |
| 第五章：技术面与动量 | 原第七章 |
| 第六章：投资观点卡片（必须含免责声明） | 原第八章 |

#### 写入个股文件
- 路径：`~/Documents/notes/Finance/{题材名}/{公司名}-分析-{YYYYMMDD}.md`
- 文件已存在时直接覆盖，不中断流程
- 完成后向用户报告：`[{i}/{N}] 完成：{公司名} → {文件路径}`

### Phase 3: 生成题材总览报告

所有个股分析完成后，生成一份题材总览，写入：
`~/Documents/notes/Finance/{题材名}/{题材名}-题材总览-{YYYYMMDD}.md`

题材总览包含以下五个部分：

#### 一、题材背景
- 该题材的核心驱动逻辑（政策/技术/需求侧，2-3 段）
- 当前所处周期阶段判断

#### 二、横向对比表
所有个股并排对比，一行一只股票：

| 公司 | 代码 | 市值(亿) | PE(TTM) | PB | 营收增速(YoY) | 净利增速(YoY) | ROE | 毛利率 | 20日动量 | 换手率 |
|---|---|---|---|---|---|---|---|---|---|---|

表格下方附统计摘要（最大/75%/中位/25%/最小），便于快速定位极值。

#### 三、分档评级
综合三个维度打分，每维度独立判断后综合定档：

**维度评判标准（基于题材内相对水平，非绝对值）：**

| 维度 | 优 | 中 | 弱 |
|---|---|---|---|
| 质地（ROE、毛利率、现金流/净利比） | 题材内 ROE 排名前 1/3，且现金流/净利 > 0.8 | 中间水平或个别指标偏弱 | ROE 排名后 1/3，或现金流持续负 |
| 估值（PE/PB） | PE/PB 均低于题材内中位数 | PE 或 PB 之一偏高，另一合理 | PE/PB 均高于题材内 75% 分位 |
| 动量（20 日涨跌幅） | 20 日涨幅 > 5% 且高于题材均值 | 涨幅 0%-5% 或略低于题材均值 | 20 日跌幅 > 0% 且落后于题材均值 |

**定档规则（三维综合）：**
- **[推荐关注]**：质地"优"+ 估值"优或中"+ 动量"优或中"（质地是必要条件）
- **[观察]**：不满足推荐关注，但质地或动量至少一项"优"，且估值非"弱"
- **[谨慎]**：估值"弱"，或质地"弱"且动量"弱"

每档列出个股，附 1 句理由（说明主要优势或主要瑕疵）。

#### 四、行业与竞争格局
- 行业周期定位与增长驱动（题材层面统一分析，不重复在个股报告里写）
- 题材内部竞争格局：谁是龙头、差异化在哪
- 核心共性风险

#### 五、精选标的
综合三个维度，从题材内推荐 1-3 只重点关注标的，每只附：
- 推荐理由（2-3 句）
- 核心风险（1 句）
- 参考目标价区间

**免责声明：本分析仅供参考，不构成投资建议。**

### Phase 4: 向用户汇报

```
题材分析完成：{题材名}
个股报告：{N} 份，路径：~/Documents/notes/Finance/{题材名}/
总览报告：{题材名}-题材总览-{YYYYMMDD}.md

精选标的：{公司A}、{公司B}
数据缺失：{若有，列出哪只股票缺了什么}
```

## 约束

- 所有分析基于 myTrader 系统中的实际数据，不编造数字
- 估值参数明确标注来源和假设
- 区分事实和分析，分析部分标注"判断"/"估计"
- 报告末尾必须包含免责声明
- 不使用 emoji
